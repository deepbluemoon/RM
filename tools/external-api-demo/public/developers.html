연동 가이드

    
계약위험탐지 공개 API 를 우리 서비스에 붙일 때 지킬 것. 원문은 서비스의 「API 활용」 화면과 모델 API 사용자 매뉴얼입니다.


    

      
1. 주소와 인증

      

        
기본 주소https://p2.sumzip.com/api/model

        
인증Authorization: Bearer crd_… — 계정마다 발급(최대 5개 동시 사용). 원문은 발급 순간 한 번만 보이고, 서비스는 해시만 저장합니다.

        
호출 위치우리 서버에서 부릅니다. 공개 API 는 CORS 를 열지 않으므로 브라우저에서 직접 부를 수 없고, 키를 브라우저 코드에 넣어서도 안 됩니다. 이 데모도 유클마켓 서버(server.mjs)가 키를 보관하고 대신 부릅니다 — 화면에는 키가 없습니다.

        
형식Content-Type: application/json, UTF-8

      

    


    

      
2. 엔드포인트

      

        
메서드 · 경로모델하는 일대략 걸리는 시간

        
GET /health—서버·모델 상태, 대기 수, 준비 예상 시간수 ms

        
GET /v1/models—모델 이름·버전 — 결과 저장 시 함께 저장수 ms

        
POST /v1/detect/loopholeM1조항별 회피형 점수(동기). 지금 모델은 유형(type)을 other 로만 냅니다~50ms (2조항)

        
POST /v1/detect/illegalM2조항별 위법형 점수(동기). 지금 모델은 related_laws 를 비워 둡니다~50ms (2조항)

        
POST /v1/jobs → GET /v1/jobs/{id}M1∥M2문서 단위 비동기 탐지. 202 {job_id} 후 조회2조항 0.7초 · 100조항 1~11초

        
POST /v1/judgeM3조항 1건 최종 판단 + 근거 인용 설명. evidence 를 빼면 서비스가 근거 DB(법령·공정위 사례·표준약관 2,547건)에서 5건을 찾아 넣습니다2~5초, 첫 호출 +10~30초

        
POST /v1/summarizeM4계약 요약 + 계약 유형 후보(최대 3)~2초

      

    


    

      
3. 이용 규칙

      

        
호출 한도키 기준이 아니라 접속 주소 기준 1분에 60번. 넘으면 429 rate_limited. 작업 조회(폴링)도 한 번으로 셉니다 — 이 데모는 처음 0.3초부터 촘촘히, 이후 1.5초 간격으로 조회합니다.

        
크기 한도한 번에 조항 2,000개 · 본문 3MB. 조항은 512토큰(약 700~900자)까지 보고 뒤는 잘립니다.

        
개인정보이름·주민등록번호·전화번호 등은 가리고 보냅니다. 남아 있으면 서비스가 한 번 더 가린 뒤 처리하며 보낸 글은 저장하지 않습니다.

        
동시 처리M3·M4 는 한 번에 1건. 여러 조항은 순서대로 보내고, /health 의 queue_depth 로 대기를 안내합니다.

        
재시도연결 오류·시간 초과·5xx 만 몇 초 쉬고 다시. 4xx 는 보낸 값을 고친 뒤 보냅니다.

        
결정성같은 입력이면 같은 점수 — 결과를 캐시해도 됩니다(model_version 과 함께).

        
상태 확인화면을 열 때 1회 + 사용자가 누를 때만. 주기적 폴링 금지.

      

    


    

      
4. 오류

      

        
코드어디서뜻 · 할 일

        
401 api_key_invalid서비스키 없음·틀림·폐기됨 → 키 확인, 필요하면 재발급

        
404 MODEL_API_PATH_NOT_ALLOWED서비스공개 목록에 없는 경로·메서드

        
429 rate_limited서비스1분 60번 초과 → RateLimit 헤더의 reset 뒤 재시도

        
502 model_api_unreachable서비스모델 서버 연결 불가 → 잠시 뒤 재시도

        
400 {"detail": …}모델입력 오류(빈 clauses, 필드 누락, perspective·날짜·점수 범위, 근거 11개 이상). detail 의 위치를 보고 고침

        
404 작업이 없습니다모델job 은 1시간 뒤·재기동 시 사라짐 → 다시 생성

        
413모델/서비스조항 2,000개·본문 한도 초과 → 나눠 보냄

        
503모델적재 중·모델 없음 → 잠시 뒤, /health 확인

        
504모델시간 초과(M3·M4 300초) → 조항 줄이기, /v1/jobs 사용

      

    


    

      
5. 결과를 화면에 보일 때

      
    
        
  • label 을 먼저 봅니다. 회피형 type 은 지금 모델에서 늘 other 라 화면에 쓰지 않고, 위험 유형은 판단(/v1/judge)의 risk_type 을 씁니다.
    • 
        
  • 점수(0~1)는 "검토 필요" 신호입니다. 기준선(0.5)을 넘으면 점수가 0.9~1.00 으로 크게 올라가는 경향이 있어 크기보다 0.5 를 넘었는지가 중요합니다. 낮은 점수를 "안전"으로 단정하지 않습니다.
    • 
        
  • 위법형 모델의 related_laws 는 지금 비어 있습니다. 값이 오더라도 확정 법률처럼 보여 주지 않습니다.
    • 
        
  • 최종 판단(M3) 설명은 단정 표현을 쓰지 않고, 받은 근거의 ID 만 인용합니다. evidence 를 빼고 부르면 응답에 evidence_source: "server_search", search_mode(hybrid·bm25), 검색한 근거 evidence[](인용 여부 cited, 원문 source_url)가 붙습니다 — 화면에는 cited: true 인 것만 보여 줍니다. 직접 근거를 보내면(최대 10개) 그것만 씁니다(evidence_source: "caller").
  • 검색이 실패하면 evidence_source: "search_failed" 로 근거 없이 판단합니다 — 이때 설명이 빈 배열일 수 있습니다.
    • 
        
  • 결과는 법률 자문이 아닙니다. 중요한 결정은 전문가와 상의하도록 안내합니다.
    • 
      

    


    

      
6. 서버 코드 예시 (Node 20)


const res = await fetch('https://p2.sumzip.com/api/model/v1/detect/loophole', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${process.env.CRD_API_KEY}`,   // 키는 환경변수에만
    'content-type': 'application/json',
  },
  body: JSON.stringify({
    contract_type: 'subscription',
    clauses: [{ clause_id: 'c1', text: '구매한 이용권은 어떠한 경우에도 환불되지 않습니다.' }],
  }),
});
if (!res.ok) throw new Error(`${res.status} ${await res.text()}`);
const { results, model_version } = await res.json();
