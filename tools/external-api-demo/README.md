# 외부 이용자 시연 — 유클마켓 회원가입 + AI 약관 위험 분석

가상의 외부 업체 **유클마켓**이 자기 회원가입 화면에 계약위험탐지 공개 API(`https://p2.sumzip.com/api/model`)를 붙인 사례.
화면을 열면 버튼 없이 실제 API 로 이용약관을 분석해 가입 창의 약관 동의(전체 동의하기) 바로 위에 보여 준다(약관을 펼치지 않아도 됨).
위험 조항 카드의 [이유·근거 보기]를 누른 조항만 상세 판단(`/v1/judge`)을 부르고, 받은 결과는 페이지 안에서 캐시한다.

## 실행 방법

터미널에서 프로젝트 루트(`~/project2610`)로 이동한 뒤 아래 둘 중 하나로 띄운다. 주소(`https://p2.sumzip.com/api/model`)·포트(9596)는 기본값이라 따로 넣지 않는다.

**방법 A — 한 줄로(가장 간단)**: `crd_…` 자리에 발급받은 키 전체를 넣고, 줄을 나누지 않는다

```bash
cd ~/project2610
CRD_API_KEY=crd_… node tools/external-api-demo/server.mjs
```

**방법 B — `.env` 에 한 번 저장(발표 때 편함)**: 키가 셸 기록에 남지 않는다

```bash
cd ~/project2610
nano tools/external-api-demo/.env          # 한 줄 입력: CRD_API_KEY=crd_…   (저장 Ctrl+O → Enter, 나가기 Ctrl+X)
chmod 600 tools/external-api-demo/.env
node tools/external-api-demo/server.mjs     # 이후에는 이 줄만
```

- 끝에 `(API 키: 설정됨)` 이 나오면 성공 → 브라우저에서 http://127.0.0.1:9596 을 열거나 새로고침
- `(API 키: 없음 …)` 이면 키가 안 넘어간 것 — 방법 A 를 두 줄로 나눠 치지 않았는지, `.env` 철자를 확인
- `EADDRINUSE` 오류 = 9596 에 이미 서버가 떠 있음 → 그 터미널에서 Ctrl+C, 또는 `lsof -ti tcp:9596 | xargs kill` 후 다시 실행
- 키는 `server.mjs` 등 코드 파일에 쓰지 않는다. 서버를 띄운 터미널은 발표 동안 닫지 않는다(닫으면 서버도 꺼짐)

| 주소 | 화면 |
|---|---|
| `/` | 회원가입(발표 메인) — ① 약관 동의(ReadMe 약관 위험 분석 자동) → ② 정보 입력 → ③ 가입 완료 |
| `/developers` | 개발자용 보조 화면 — API 콘솔(7개 엔드포인트 + curl)·연동 가이드·호출 기록 |

## 표시 기준(업체 설정 — `terms-analysis.js` 의 `PARTNER`)

「확인이 필요한 조항」 = 회피형(M1) ≥ 0.5 **또는** 위법형(M2) ≥ 0.8. 모든 조항의 두 점수는 결과 아래 「전체 조항 점수 보기」에 그대로 보인다.

약관 1판(15조, 짧은 문장)은 ordneg 모델에서 정상 7개 중 6개(정의·회원가입·구매 신청·배송·개인정보 등)가 표시돼 기준값으로는 거를 수 없었다.
→ 2판(2026-10-01, 16조)으로 다시 씀: 정상 조항은 공정위 전자상거래 표준약관 문체로, 후보 16개를 실제 API 로 재서 모델이 정상으로 보는 문장만 골랐다
(떨어진 후보: 정의·약관 개정 7일 공지·회원가입·회원탈퇴·정상 청약철회 — 내용이 정상이어도 높게 나옴). 결과: 문제 8 전부 표시, 정상 8 전부 미표시(위법형 0.24~0.63).
1판 = `euclmarket-terms.v1.txt`(public 밖, 화면에 안 쓰임). 모델이 바뀌면 다시 재어 볼 것.

## 근거 표시 원칙

`/v1/judge` 에 `evidence` 를 보내지 않는다. 그러면 공개 API(백엔드)가 지식 DB(법령·공정위 사례·표준약관, 웹 분석과 같은 하이브리드 검색)에서 조항마다 근거를 찾아 넣고,
응답에 `evidence_source: "server_search"`, `search_mode`, `evidence[]`(각 항목 `cited` = 설명이 인용했는지, `source_url`)를 돌려준다(2026-10-01).
화면에는 **응답이 실제로 인용한 근거(`cited`)만** 보인다. M2 `related_laws` 는 값이 있을 때만 보인다.
`crd-client.js` 의 `EVIDENCE`(전자상거래법 제17조, 약관법 제6·7·8·9·10·14조 발췌)는 직접 근거를 보내는 예시로만 남겼다 — 보내면 서버 검색 없이 그것만 쓴다.
「쉽게 말하면」 한 줄(`EVIDENCE_PLAIN`, 유클마켓이 미리 쓴 문장 — API 에는 보내지 않음)은 인용된 근거가 미리 써 둔 법령 조문 7개 중 하나일 때 붙는다. 서버 검색 근거는 id 가 DB 번호라 `plainFor` 가 **법 이름 + 조(+ 항)** 로 찾고, 특정 항에 대한 설명은 항까지 같을 때만 붙인다(전자상거래법 제17조 제2항에는 제1항 설명을 붙이지 않음). 공정위 사례·표준약관·그 밖의 조문은 원문만.
공정위 사례 제목의 사건 식별번호(`FTC-…`)는 화면에서 숨긴다(`displayTitle`, 본 서비스와 같은 원칙).

### 용어 맞추기 · 안전한 조항 (2026-10-01)

- 판단 전 카드 칩 = 「확인 필요」(본 서비스에 없는 점수 등급 「위험 높음·주의」는 뺌) → 이유를 받으면 「불공정 가능 · ●높음」처럼 판단으로 바뀜. 점수 막대 = 「회피형/위법형 탐지 점수 0.98」
- 요약 칸 「위험 높음」 → 「문제 소지 낮음」(판단 후 바뀌는 카드와 어긋나지 않게). 탐지 점수가 기준 아래인 조항 8개를 「○ 문제 소지 낮음 · 조항 8개 보기」로 펼쳐 볼 수 있음
- 모바일 틀 안 화면이 정확히 390×844(이전엔 테두리 때문에 366)
