# 대형 화면 모니터링 설계

운영 화면의 기존 기능을 보존하고 별도 `/monitor.html` 화면을 추가한다.
운영 현황의 모드 스위치로 왕복하며 같은 출처의 실제 관측 API를 사용한다.

## 구조 스케치

```text
RM / MONITOR          연결 상태 · 마지막 관측       운영 | 모니터링 · 전체화면
───────────────────────────────────────────────────────────────────────────
전체 상태 / 활성 경고         실행 컨테이너        CPU 합계       메모리 합계
───────────────────────────────────────────────┬───────────────────────────
자원 추이 (시간에 따른 CPU·메모리, 각각의 축)     │ 자원 상위 5개 (가로 막대)
───────────────────────┬───────────────────────┼───────────────────────────
컨테이너 상태 목록      │ HTTP 응답 구성 (누적 막대)│ 활성 경고 / 운영으로 연결
───────────────────────┴───────────────────────┴───────────────────────────
실제 수집 · 갱신 간격 · 데이터 범위                           현재 시각
```

## 목적과 데이터 표현

- 상태 요약: 멀리서 장애 유무와 실행 규모를 읽는다. 상태 문구와 색을 함께 사용한다.
- 추이: 현재 화면을 연 이후 관측한 값만 표시한다. CPU 합계는 100%를 넘을 수 있으며 메모리는 실사용량이다.
- 순위: 자원 사용이 큰 컨테이너를 공통 기준 막대로 비교한다.
- 응답: 로그에서 수집한 응답의 분포이며 전 서비스 요청량이나 응답 지연으로 표현하지 않는다.
- 경고: 원인을 읽고 운영 화면으로 이동한다. 모니터링 화면에는 변경 명령을 두지 않는다.
- 연결 실패·오래된 관측·빈 데이터는 정상이나 0으로 위장하지 않는다.

## 시각 방향과 검증

검정/짙은 남색 바탕, 청록 강조, 큰 숫자, 얇은 구획선, 넓은 추이 차트.
1920×1080 및 3840×2160에서 비례 확장하고 작은 화면은 스크롤을 허용한다.
모드 전환은 수평 View Transition과 미지원 브라우저 대체 동작, 모션 감소 설정을 제공한다.
레퍼런스: https://kr.pinterest.com/hyunjee1009/대시보드-레퍼런스/

main 최신 상태에서 분기하며 병합 직전에 origin/main을 다시 반영하고 충돌 및 검사를 수행한다.
운영 컨테이너를 바꾸지 않고 별도 로컬 포트에서 미리 확인한다.
