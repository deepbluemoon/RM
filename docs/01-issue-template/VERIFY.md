# 검증 기록

## 범위

2026-10-30, 탐지 프로젝트에 맞춘 템플릿 개정의 검증 기록이다. 이전 작성 단계의 통과 기록을 현재 상태의 증거로 재사용하지 않는다.

## 파일 검사

- 실제 적용본·changes·completed의 템플릿 3종 각각 SHA-256 일치: 통과.
- 템플릿 3종의 front matter 경계·name·about·title: 통과. 고정 문자열 구조 검사이며 GitHub 렌더링 검증은 아니다.
- 템플릿·패키지 문서·AGENTS.md 총 17개 파일의 후행 공백·NUL 검사: 통과.
- 고정 SSH 경로·과거 비교 커밋·백업 후보 경로 잔존 검사: 통과.
- 실제 프로젝트 디렉터리와 package.json, 모델 상태 코드 대조: 확인. 실행 가능성·탐지 정확도를 증명하지는 않는다.
- git diff --check 및 git diff --cached --check: 통과.
- 새 파일은 Git diff에 포함되지 않을 수 있어 위 파일 내용 검사로 별도 확인했다.
- 기존 브랜치 issue-template-runtime-audit를 유지하고 기존 인덱스를 변경하지 않았다.
- Git 상태: 기존 템플릿 2개는 AM(기존 스테이징 이후 작업 파일 수정), feature_request.md·AGENTS.md·문서 폴더는 미추적 상태다. 커밋 전 최종 내용을 다시 선택해 스테이징해야 한다.
- 루트 AGENTS.md에서 GUIDE와 템플릿을 참조하도록 연결해 이후 AI 작업의 범위·검증·push 기준에 반영했다.

## 시나리오 검토

다음은 문서의 분기·판정 규칙을 대입한 검토다. 독립 AI 반복 실행이나 실제 서비스 테스트가 아니다.

| 상황 | 기대하는 처리 | 문서 검토 결과 |
|---|---|---|
| 최소 구동 조건만 조사 | 조건·근거·부족한 조건을 정리하고 설치·기동은 후속 작업으로 분리 | ISSUE 예시와 runtime·GUIDE에 명시 |
| SSH·백업 접근 불가 | 기본 요구에서 제외하고 목표에 필요한 경우에만 의존성으로 취급 | 고정 SSH 경로와 백업 후보 제거 |
| 개발용 스텁 사용 | 실모델 자산은 필요 여부를 판정하고 실모델 품질 검증으로 보고하지 않음 | runtime·feature·GUIDE에 명시 |
| 정적 분석 버그 | 실행 재현 안 함과 관찰·가설을 구분하고 필수 검증이 남으면 완료 보류 | bug·GUIDE에 명시 |
| 탐지 기능 개선 | 비식별 사례·기대 판정·비교 기준·정상 및 오류 조건을 먼저 정의 | feature에 명시 |
| 필수 검증 차단 | 이유·영향·다음 조치를 기록하고 구현·검증 완료로 보고하지 않음 | 세 양식·GUIDE에 명시 |

## 미실행 범위

- 앱 설치·빌드·DB 초기화·기동·모델 다운로드·실모델 분석·탐지 정확도 평가.
- GitHub 웹 템플릿 선택·렌더링 확인.
- 독립된 AI의 반복 작업 성공률 측정.
- 스테이징·커밋·push·GitHub 이슈 및 PR 생성. 기존 스테이징은 보존한다.

## 2026-10-30 추가 기록 — 공통 PR 템플릿과 제목 규칙

위 항목은 이전 이슈 템플릿 정비 작업의 기록으로 보존한다. 아래는 `docs/contributing-guide`에서 추가한 PR 템플릿과 기여 안내에 대한 별도 검증이다. 과거 기록의 브랜치·Git 상태·실행 결과를 이번 작업의 결과로 재사용하지 않는다.

### 범위

- 루트 `.github/pull_request_template.md`와 changes·completed의 같은 상대 경로 사본 2개.
- 루트 `CONTRIBUTING.md`의 PR 제목 형식·본문 링크·자동 입력 적용 시점 안내.
- GUIDE·README·EXPLANATION의 PR 템플릿 유지보수 안내와 이 추가 검증 기록.

### 확인 결과

- PR 템플릿 3개 파일의 SHA-256 일치: 통과.
- 변경 문서·템플릿 8개 파일의 상대 링크·후행 공백·NUL·코드 블록·HTML 주석 경계 확인: 통과. 새 파일은 Git diff에 포함되지 않을 수 있어 직접 검사했다.
- 목적·변경·검증·관련 이슈·남은 사항·AI 도움·공유 전 확인의 본문 항목 확인: 통과.
- PR 제목은 직접 입력하고, GitHub 본문 자동 입력은 기본 브랜치 반영 후 이용한다는 안내: 확인.
- GUIDE의 diff·staging 예시에 루트 PR 템플릿과 CONTRIBUTING 포함, 과거 커밋 메시지 파일의 자동 재사용 제거: 확인. 문서 예시를 검토했으며 실제 staging·commit은 실행하지 않았다.
- 기존 이슈 템플릿 3종의 적용본·사본 총 9개와 기존 AGENTS·사용자 DB 정리 문서의 내용 보존: 통과.
- `git diff --check`: 통과. 실제 staged 파일은 없으며 기존 인덱스를 변경하지 않았다.

### 미실행과 적용 한계

- GitHub PR 작성 화면에서 본문 자동 입력·렌더링 확인: 미실행. 로컬 파일 추가만으로 기본 브랜치 적용을 완료한 것은 아니다.
- 앱 실행·빌드·모델 추론: 해당 없음. 이번 변경은 문서·양식 작업이다.
- 스테이징·커밋·push·원격 PR 생성·GitHub 보호 설정 변경: 미실행.
- 필수 승인 인원·병합 주체·Co-Authored-By 규칙 확정: 별도 정책 작업 범위이며 이번 변경으로 결정하지 않았다.
