# [Runtime] 계약위험탐지서비스 RM의 최소 구동 조건을 정리한다

## 문제와 목표

현재 RM을 최소한으로 구동하려면 어떤 코드·설정·DB·모델·근거 데이터가 필요한지 정리한다. SSH 서버 비교나 백업 확보가 목적이 아니다. 설치·기동 전에 필요한 조건과 부족한 조건을 구분하는 조사 작업이다.

## 작업 유형과 범위

- 유형: 조사.
- 기준 커밋·브랜치·기존 변경: 조사 시작 시 기록한다.
- 개발용 스텁 / 외부 모델 서버 연결 / 독립 실모델의 최소 조건을 구분한다.
- 적용할 구동 범위가 정해지지 않았으면 차이와 선택에 필요한 판단 근거를 남긴다.
- 앱 수정·설치·DB 초기화·모델 다운로드·컨테이너 구현·SSH 및 백업 확보는 제외한다.

## 확인할 내용

- [ ] frontend/·backend/·tools/model-api-stub/·model-server/의 실행 명령과 버전 조건.
- [ ] 선택한 흐름에 필요한 설정 키·연결 주소·쓰기 경로와 공통 자산.
- [ ] DB 연결·마이그레이션·개발용 계정과 초기 데이터의 필요 여부.
- [ ] 실모델 범위의 M1·M2 가중치·토크나이저·모델 카드와 heuristic 대체 조건.
- [ ] 분석·설명·근거 검색에 필요한 채팅·임베딩 모델 및 지식·임베딩의 호환 조건.
- [ ] 로그인 → 입력 → 분석 → 근거·결과 → 이력 중 각 범위에서 확인 가능한 동작과 한계.

## 완료 조건

- [ ] 최소 조건을 현재 코드·설정·명세 근거와 연결했다.
- [ ] 존재 확인·정적 추론·실행 확인을 구분했다. 미실행 항목을 성공으로 표시하지 않았다.
- [ ] 필요한 설정은 키와 용도만 기록하고 운영 비밀값·사용자 데이터를 포함하지 않았다.
- [ ] 부족한 자산·접근 제한이 있으면 영향과 다음 조치를 기록했다.
- [ ] 실제 구동·코드 수정은 필요한 경우 별도 후속 작업으로 분리했다.
